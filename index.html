elSpectro

An Interactive Guide to the Event Generation Framework

Core Concepts

Core Library (`libelSpectro`)

This is the heart of the framework. It is a shared library that contains all the fundamental physics classes and logic for defining particles, managing decays, and modeling reactions.

Apps Executables

These are standalone programs that use the `core` library. The primary executable, `elSpectro`, acts as a custom ROOT environment that simplifies running simulation scripts.

0. The Initial State: `CollidingParticle`

Role: To represent the stable particles that initiate the event—the beam and target.

Key Feature: They are the *inputs* to the `ProductionProcess`. They are not part of the decay chain themselves but are used to define its starting conditions.

Interaction: Before the event loop begins, the user creates instances of `CollidingParticle` (e.g., an electron and a proton) and provides them to the `ProductionProcess` object.

Analogy: `CollidingParticle`s are the raw ingredients for a recipe. They are consumed at the beginning to create the initial mixture.

1. The Setup: `ProductionProcess`

Role: To model the initial collision using the provided `CollidingParticle` objects and to define the properties of the interaction's center-of-mass (CoM) system.

Key Feature: As a `DecayingParticle`, its "decay" is a special step that consumes the initial `CollidingParticle`s to produce a single, virtual daughter particle: an instance of a `Formation` class.

Interaction in Electron Scattering:

  1. An `ElectronScattering` object is created and configured with the beam and target `CollidingParticle`s.
  2. It uses their four-momenta to calculate kinematic variables, such as $Q^2$ and $W$.
  3. It then "decays," creating one `FormationQ2W` particle and setting its mass to $W$.

Analogy: The `ProductionProcess` is the chef. It takes the ingredients (`CollidingParticle`s) and prepares them, creating an intermediate dish (the `Formation` object) ready for the final cooking stage.

2. The Center-of-Mass System: `Formation` Object

Role: To represent the combined, virtual state of the colliding particles at the center of mass (the $\gamma^* + \text{nucleon}$ system).

Key Feature: It is the first dynamic `DecayingParticle` of the reaction, serving as the parent for all subsequent hadronic products.

Interaction:

  1. The `Formation` particle, having been created by the `ProductionProcess`, is now instructed to decay.
  2. It delegates this task to its own `DecayChannel`.

Analogy: The `Formation` object is the prepared dish, now in the oven. Its "decay" is the process of it cooking and separating into its final, served components.

3. The Hadronic Decay: `DecayChannel` & Co.

This part of the process happens *to the `Formation` object*, orchestrating its decay into the final state hadrons. This is a multi-step process managed by several classes:

  • `DecayChannel`: Orchestrates the decay of the `Formation` object.
  • `DecayModel`: A model within the channel is selected to determine the identities of the final state hadrons (e.g., a proton, a $\pi^+$, and a $\pi^-$). This answers "what" particles are produced.
  • `DecayVectors`: The corresponding object then calculates the four-momenta of these hadrons in the CoM frame. This answers "how" they move.

If any of the new hadrons are also unstable (`DecayingParticle`s), this process repeats for each of them in a cascade until only stable particles remain.

Build & Usage Guide

1. Build Commands

git clone --recursive https://github.com/dglazier/elSpectro.git
cd elSpectro
cmake -S . -B build -DCMAKE_INSTALL_PREFIX=install
cmake --build build
cmake --install build

2. Environment Setup (bash/zsh)

export ELSPECTRO_INSTALL_DIR="/path/to/your/install"
export PATH="$ELSPECTRO_INSTALL_DIR/bin:$PATH"
export LD_LIBRARY_PATH="$ELSPECTRO_INSTALL_DIR/lib:$JPACPHOTO/lib:$LD_LIBRARY_PATH"

3. Run a Simulation

elSpectro my_simulation.C
